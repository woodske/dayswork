## Decisions / Deviations
- **DEV-01** [U-13B / worker actor decision]: Farmer re-founding was implemented and play-tested, then rejected due to standalone `Farmer` rendering depth issues, body-pose corruption risk, movement mismatches, and vanilla tool animation callbacks that assume real player state. Accepted direction is an NPC-backed worker in the normal farm character list, with explicit Dayswork task execution and custom callback-free task animation. Visible tools are represented by world `TemporaryAnimatedSprite` swings inspired by Stardew Squad rather than by invoking full vanilla Farmer tool animations. Post-v1 worker energy/tools/food/buffs should be modeled explicitly rather than depending on hidden `Farmer` behavior.
- **DEV-U14-01** [U-14 / FR-OUT-05, FD-Q7]: Tool-missing warning mail is sent through MFM as a **text-only (no-attachment)** letter rather than vanilla `Game1.addMailForTomorrow` (the FD-Q7=A / plan wording). Reason: vanilla custom mail can't cleanly carry per-shift dynamic text (the skipped-task list) and re-deliver daily; MFM (already a required dependency) handles text-only letters cleanly. FD-Q7=A's behavioural intent (one separate combined no-item warning per shift, listing skipped tasks) is preserved.
- **DEV-U14-02** [U-14 / NFR-SAFE-01]: `ShiftOrchestrator.OnSaving` mid-work branch (player sleeps while worker still working, `ShiftEndTime` unset) now **mails the collected items** instead of discarding them, while keeping the existing full-deposit refund. The later U-15 fast-forward idea was superseded by DEV-U15-09 sleep-stop settlement.
- **DEV-U14-03** [U-14 / MFM integration]: The guessed `IMailFrameworkModApi.RegisterLetter(id, synopsis, text, attachments)` stub was replaced after inspecting the installed Mail Framework Mod at `X:\Steam\steamapps\common\Stardew Valley\Mods\MailFrameworkMod`. Confirmed MFM `1.20.0` exposes `RegisterLetter(ILetter, Func<ILetter,bool>, Action<ILetter>, Func<ILetter,List<Item>>)`. Dayswork now uses `MailFrameworkModApiAdapter` to fetch the raw API object via `GetApi("DIGUS.MailFrameworkMod")`, create MFM `Letter`/`ApiLetter` instances by reflection, and pass a deliver-after-queued-day condition. `manifest.json` now declares `MinimumVersion` `1.20.0`. If binding/registration fails, `MailDispatcher` still falls back (overflow → shipping bin, warning → log) so no items are lost.
- **DEV-U15-01** [U-15 / FR-HIRE]: v1 supports at most one Active/Paused contract at a time; enforced at hire time (bulletin board offers "Hire" only when none exists). Resolves TODO-04 for v1; the orchestrator manages a single worker. Multi-worker/merge deferred post-v1. *(FD-Q1=A)*
- **DEV-U15-02** [U-15 / FR-DAY-01]: Festival days are skipped **and a courtesy letter is sent** (deviates FR-DAY-01 "no mail"). Recurring: no deposit, stays Active, text-only same-day letter. One-time (BR-CAL-03, open sub-decision pending approval): marked Executed + same-day mailed full refund (alternative: roll to next non-festival day). *(Clar-1a=C; playtest timing correction DEV-U15-06)*
- **DEV-U15-03** [U-15 / FR-TOOL-03]: A missing tool degrades to the lowest-tier (basic) tool; the worker performs the task with no skip and no warning. Owned-tool tier gating unchanged (basic pickaxe still can't break boulders; fruit trees always-skip). The tool-missing warning path is removed (`ShiftContext.ToolMissingWarnings` + `MailDispatcher.QueueToolMissingWarning`), superseding U-14 BR-MAIL-05. *(FD-Q8=C, Clar-2a/2b/2c=A)*
- **DEV-U15-04** [U-15 / FR-PAY-05]: Shift settlement refunds (normal exit, sleep-stop, empty-zone) are delivered as gold-bearing mail the next morning instead of credited directly at exit. Deposit still leaves gold immediately (FR-PAY-03); only the return is delayed one day. `IntentApplyRefund` routes to the settlement letter; ≤1 settlement letter per shift (overflow items + refund gold). Fallback if MFM can't attach money: text-only letter crediting gold on collection. *(FD-Q9=C, Clar-3=A)*
- **DEV-U15-05** [U-15 / FR-PAY-07]: On rainy days only the Water Crops *surcharge* is excluded from the rate; the task is **not** force-skipped (refines FR-PAY-07 "watering task is skipped"). Outdoor crops are rain-watered so the worker skips them naturally; the task stays available for future building-interior crops (TODO-05). *(FD-Q4=B)*
- **DEV-U15-06** [U-15 / playtest / mail timing]: Morning no-worker notices are same-day mailbox letters. `QueueFestivalNotice` and `QueueCannotAffordNotice` register MFM letters with today's earliest delivery day and add the letter id to `Game1.mailbox`; settlement/refund/overflow letters remain next-morning. Reason: a festival skip letter arriving after the festival is not useful. *(Playtest feedback 2026-05-22)*
- **DEV-U15-07** [U-15 / playtest / recurring deposit]: Recurring day-start deposits use shared `DepositHoursPolicy.FlatPreviewHours` (1.0 billable hour), matching the hire summary screen, instead of raw tile-based `HoursEstimator`. Reason: saved building placeholder zones `(0,0)..(999,999)` caused impossible recurring deposits such as 36,755,660g. Revisit with the future HoursEstimator/pricing fix. *(Playtest feedback 2026-05-22)*
- **DEV-U15-08** [U-15 / playtest / MFM attachments]: No-attachment letters register without an MFM `dynamicItems` provider, and empty settlement letters are suppressed. Reason: MFM showed an empty item slot for letters that carried no item. *(Playtest feedback 2026-05-22)*
- **DEV-U15-09** [U-15 / playtest / sleep]: Sleeping stops the worker instead of running remaining work headlessly. Collected-but-undelivered items and any unearned refund are mailed; remaining world work stays undone. Reason: sleep fast-forward was not reliable enough for v1, and hard-stop settlement is simpler and predictable. *(Playtest feedback 2026-05-22)*
- **DEV-02** [U-13 / FR-WORK-03]: Outdoor work routing now uses greedy nearest-next selection across currently detected non-animal tasks instead of fixed task-kind priority among grass/weeds/rocks/trees/crops. Distance is measured to the task tile, while the worker's current physical position remains the last navigation tile. Detection checks placed objects/resource clumps before grass so grass cannot mask rocks/weeds/twigs on the same tile. Blocked targets resolve to a reachable orthogonal stand tile; walkable targets use the task tile with an orthogonal fallback when the task tile is not passable. Resource clumps now classify into axe/pick work using Stardew constants (`stumpIndex`, `hollowLogIndex`, `boulderIndex`, `meteoriteIndex`, etc.), search for a stand tile around the whole clump footprint, and are removed by the matching invocation handlers. Regular stone objects are revalidated as pick targets and removed deterministically after the simulated pickaxe action so a false `performToolAction` return cannot silently complete a shift without clearing accepted rocks. User play-test feedback: worker should perform whichever thing is closest, with animal tasks as the future exception. Animal tasks are assigned to U-16 and can regain first-priority handling there.
